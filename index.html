SELECT & FROM

The two clauses you use in every single SQL query.

The concept

SELECT tells SQL which columns you want to see. FROM tells SQL which table to look in. That's it. Every query starts here.

SELECT column_name, another_column
FROM table_name;

To get everything from a table, use * (star):

SELECT *
FROM rides;
The table you're working with

For the next few lessons, you have a table called rides — Forest bike ride data.

Lesson 2 of 7

WHERE

Filter which rows you get back.

The concept

WHERE filters rows before anything else happens. Only rows that match the condition come through.

SELECT *
FROM rides
WHERE city = 'London';

Common operators: =   !=   >   <   >=   <=

Combine conditions with AND / OR:

SELECT *
FROM rides
WHERE city = 'London' AND duration_minutes > 20;
"WHERE filters rows. You decide which rows survive before anything else runs."
Practice — write the query

Write a query that returns all columns for rides where the duration was more than 15 minutes.

SELECT * FROM rides WHERE duration_minutes > 15
Lesson 3 of 7

GROUP BY & Aggregates

Collapse rows into groups and calculate something about each group.

The concept

Aggregate functions do a calculation across multiple rows: COUNT, SUM, AVG, MAX, MIN.

GROUP BY collapses rows with the same value into one row, then runs the aggregate on each group.

SELECT station_id, COUNT(ride_id) AS total_rides
FROM rides
GROUP BY station_id;

The AS keyword gives your calculated column a name you can reference later.

-- Result:
-- station_id | total_rides
-- ST01 | 2
-- ST02 | 2
-- ST03 | 1
"GROUP BY is how you answer 'how many per X' or 'average Y per X' questions. Every column in SELECT must either be in GROUP BY or inside an aggregate function."
Practice — write the query

Write a query that shows each station_id and the average duration_minutes for rides at that station. Name the average column avg_duration.

SELECT station_id, AVG(duration_minutes) AS avg_duration FROM rides GROUP BY station_id
Lesson 4 of 7

HAVING

Filter groups after GROUP BY. The most commonly confused clause.

The concept

WHERE filters rows before grouping. HAVING filters groups after grouping. You cannot use WHERE to filter on an aggregate — that's what HAVING is for.

-- WRONG — can't use WHERE on an aggregate
SELECT station_id, COUNT(ride_id) AS total_rides
FROM rides
GROUP BY station_id
WHERE total_rides > 1; -- ❌ error
-- CORRECT — use HAVING to filter groups
SELECT station_id, COUNT(ride_id) AS total_rides
FROM rides
GROUP BY station_id
HAVING COUNT(ride_id) > 1; -- ✓
"WHERE = filter rows. HAVING = filter groups. If you're filtering on something you calculated with COUNT, SUM, or AVG — it's HAVING."
Practice — write the query

Write a query that shows only the stations where the average ride duration is greater than 15 minutes.

SELECT station_id, AVG(duration_minutes) AS avg_duration FROM rides GROUP BY station_id HAVING AVG(duration_minutes) > 15
Lesson 5 of 7

ORDER BY & LIMIT

Sort your results and cap how many rows come back.

The concept

ORDER BY sorts results. ASC = smallest first (default). DESC = largest first.

LIMIT caps the number of rows returned.

SELECT station_id, COUNT(ride_id) AS total_rides
FROM rides
GROUP BY station_id
ORDER BY total_rides DESC
LIMIT 3;

This returns the top 3 busiest stations.

"The full clause order: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT. You don't need all of them, but they must appear in this order when you do."
Practice — write the query

Write a query that returns the single bike with the highest total number of rides. Show the bike_id and the count, named ride_count.

SELECT bike_id, COUNT(ride_id) AS ride_count FROM rides GROUP BY bike_id ORDER BY ride_count DESC LIMIT 1

JOINs

Connect two tables together using a shared column.

Two tables

You now have a second table: stations.

station_idstation_nameborough
ST01London BridgeSouthwark
ST02Shoreditch High StHackney
ST03PiccadillyWestminster

Both tables share station_id. That's the key you JOIN on.

INNER JOIN — only matching rows
SELECT rides.ride_id, stations.station_name, rides.duration_minutes
FROM rides
INNER JOIN stations ON rides.station_id = stations.station_id;

Only returns rows where station_id exists in both tables.

LEFT JOIN — all rows from left table
SELECT rides.ride_id, stations.station_name
FROM rides
LEFT JOIN stations ON rides.station_id = stations.station_id;

Returns all rides — even if no matching station exists. Missing station values show as NULL.

"INNER JOIN = only where both sides match. LEFT JOIN = everything from the left table, matched or not."
Practice — write the query

Write a query that shows each ride's ride_id, the station_name it started from, and the duration_minutes. Use an INNER JOIN.

SELECT rides.ride_id, stations.station_name, rides.duration_minutes FROM rides INNER JOIN stations ON rides.station_id = stations.station_id
Lesson 7 of 7 — most important

Read a Table → Answer a Business Question

This is the exact format of the Palantir CodePair round.

The skill

In the interview you'll be given a data table and a business question. Your job: read the table, identify what it contains, write a query that answers the question, and explain your reasoning out loud.

The interviewer is watching three things: do you understand what the data represents, do you write the right query, and do you narrate your thinking.

NHS scenario — the table

You are working with an NHS trust. Here is a table of patient appointments:

appointment_idpatient_idwardappointment_dateattendedwait_days
A001P01Cardiology2024-01-10112
A002P02Oncology2024-01-11028
A003P03Cardiology2024-01-1218
A004P04Neurology2024-01-13045
A005P05Oncology2024-01-14131
A006P06Cardiology2024-01-15019

attended: 1 = attended, 0 = did not attend (DNA)

Business question 1

The trust director wants to know which ward has the highest DNA (did not attend) rate. Write the query.

You need to COUNT appointments per ward, then COUNT where attended = 0, then calculate a ratio. Or simpler: SELECT ward, SUM(CASE WHEN attended = 0 THEN 1 ELSE 0 END) AS dna_count FROM appointments GROUP BY ward ORDER BY dna_count DESC LIMIT 1
Business question 2

Which wards have an average wait time of more than 20 days? Show the ward and average wait, named avg_wait.

SELECT ward, AVG(wait_days) AS avg_wait FROM appointments GROUP BY ward HAVING AVG(wait_days) > 20

Quick Reference

Everything you need on one page. Print this or keep it open.

Clause order — always in this sequence
SELECT -- what columns
FROM -- which table
JOIN -- connect another table
WHERE -- filter rows (before grouping)
GROUP BY -- collapse into groups
HAVING -- filter groups (after grouping)
ORDER BY -- sort results
LIMIT -- cap number of rows
Aggregate functions
COUNT(column) -- number of rows
SUM(column) -- total
AVG(column) -- average
MAX(column) -- highest value
MIN(column) -- lowest value
WHERE vs HAVING
-- WHERE filters rows (use before GROUP BY)
WHERE city = 'London'

-- HAVING filters groups (use after GROUP BY)
HAVING COUNT(ride_id) > 5
JOINs
-- INNER JOIN: only matching rows
FROM rides INNER JOIN stations
ON rides.station_id = stations.station_id

-- LEFT JOIN: all left rows, matched or not
FROM rides LEFT JOIN stations
ON rides.station_id = stations.station_id
The three DS rules for SQL in interviews

1. Narrate everything out loud as you type — silence is unreadable.

2. Write something that works first, then improve it.

3. If you're stuck, ask a clarifying question — they expect it and want to see it.
